# 验收与交付计划

日期：2026-10-22；状态：所有必需开发模块及项目验收已完成，含真实 DeepSeek 和解压源码包验证。课程平台上传和可选视频未执行。实际证据见 [最终验收报告](FINAL_ACCEPTANCE.md)。

## 1. 核心验收矩阵

| 场景 | 对应需求 | 预期证据 |
| --- | --- | --- |
| 空任务、超长任务或无效路径 | F01 | Agent 未启动，退出码 2，明确错误 |
| 首次审查直接通过 | F02、F03、F05 | 编码和审查完成，修复 skipped，退出码 0 |
| 审查拒绝、一次修复后通过 | F02—F07 | 三角色协作、v1/v2、两份版本匹配报告，状态 succeeded |
| 持续拒绝 | F05 | 恰好两次修复、三次审查，needs_attention，退出码 3 |
| 审查报告格式无效或版本错配 | F03、F10 | 不进入错误的下游节点，failed，退出码 1 |
| 超时后重试成功 | F09、F10 | 同节点两次尝试，不重复增加 repair_count |
| 超时重试仍失败或鉴权失败 | F09、F10 | 前者最多两次尝试，后者一次；失败定位清楚 |
| 保存产物时失败 | F07、F10 | 非零退出，不输出 succeeded；已有产物可检查 |
| 两次独立运行 | F06、F07 | 不同运行目录、消息与代码版本均不串线 |
| 替换模型实现 | F09 | 相同角色与编排契约下分别使用 Mock、真实 Provider |
| 模型配置缺失 | F09 | 配置错误退出码 2，不静默使用 Mock |

## 2. 人工语义验收

准备三个小型 Python 纯函数任务：空列表求和、括号配对校验、保留顺序的列表去重。每个任务明确正常、边界和无效输入的预期行为。检查候选代码与需求是否相符、报告能否指出可复现问题、修复是否对应问题 ID。

Mock 场景使用预置响应验证调度；人工语义验收使用真实模型产物并记录判断理由。固定场景通过不能证明模型能力，也不能证明任意代码正确。

## 4. 验收记录格式

实现后逐项记录：场景、运行命令、日期、代码 commit、Mock/真实模式、结果目录、预期与实际、通过/失败/未执行、失败原因。依赖锁定后补充实际安装与测试命令，不使用未经验证的运行说明。
