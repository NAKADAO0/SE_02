# 项目目标与范围

版本：0.1；日期：2026-10-22；状态：待评审设计。

## 1. 产品定位

面向软件工程课程演示，提供小型 Python 编程任务的三 Agent 代码审查工作流。核心价值是让“谁生成、谁审查、谁修复、数据如何流转、失败发生在哪一步”能够被直接观察。

目标用户为课程开发者、演示者及评审者。首期聚焦单文件、纯函数类任务，如字符串处理、列表计算与输入校验。

## 2. 方案比较与选择

| 方向 | 优点 | 主要代价 |
| --- | --- | --- |
| 三 Agent 代码审查（建议方案） | 角色边界明确，缺陷与修复易演示，可展示复审闭环 | 需约束代码和审查报告格式 |
| 分析与文档生成 | 两个角色即可跑通，产物直观 | 正确性评价较依赖人工判断 |
| 需求、设计、编码 Mini SE | 覆盖软件工程阶段较完整 | 阶段产物多，短期内验收范围较大 |

本期采用建议方案作为文档基线，不同时开发其他方向。

## 3. 必须满足的课程要求

1. 至少两个 Agent 协作完成端到端流程；本方案设置三个独立角色。
2. Agent 之间通过结构化消息和共享运行状态传递结果。
3. 编排器支持基本顺序执行。
4. MVP 能实际运行，不依赖复杂调度。

截图推荐但非硬性要求的能力：条件分支、循环、并行、可视化编排、日志与状态追踪、错误恢复。本方案选入有界复审、执行日志及基本错误处理；并行和拖拽编排不纳入首期。

## 4. 可衡量目标

| 目标 | 达成证据 |
| --- | --- |
| 完整闭环 | 演示一条编码、审查拒绝、修复、复审通过的记录 |
| 消息可追踪 | 每个消息含 run_id、消息 ID、发送方、接收方及载荷引用 |
| 状态明确 | 每次运行有终态；失败保留阶段、原因和已有产物 |
| 流程有界 | 最多两轮修复，超限以 needs_attention 结束 |
| 易于扩展 | 新角色可实现统一接口并注册，编排器不依赖具体模型 SDK |
| 可复现演示 | Mock 成功、失败和超限场景不需要密钥或网络 |
| 真实能力验证 | 配置模型后留存一份脱敏的真实运行记录；无环境时明确记为未验收 |

## 5. 范围边界

首期提供命令行、结构化审查报告、运行目录和日志；不承诺生产级代码正确性。代码通过审查仅表示满足本系统审查规则，人工验收仍检查任务需求。

不做多用户账号、云部署、任意仓库自动修改、生成代码自动执行、并行调度和可视化流程编辑器。首期代码作为文本产物保存，不自动安装依赖或执行模型输出。

旧作业模块仅在后续确认兼容性、依赖和接口后选择性复用；没有已完成复用的假设。
